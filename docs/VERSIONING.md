# 版本号规则

本插件从上游 `dsh-purge@1.1.71-rc2.1` 接続，遵循一条原则：**改动多大，版本就动多少；不动宿主契约，永不进 2.x。**

## 三段式含义

| 段 | 什么时候 +1 | 例子 |
|---|---|---|
| `major` | **不动**。只有换宿主大版本、需要重写补丁契约时才考虑 | 1.x.y 固定 |
| `minor` | 成体系的升级：新增页签、新增注入层、新增接口、改变面板结构 | 1.1.x → 1.2.0 |
| `patch` | 小改动：修文案、改样式、补一条规则、加一个兜底、修一个锚点 | 1.1.72 → 1.1.73 |

## 现行版本线

```
1.1.71-rc2.1   上游原版（小杨 / MIT）
1.1.72         破甲注入层 V2–V4、第三页签「破甲」、16 个 Skill、面板兜底列表、版本回退到渐进式
```

## 怎么改（别手改）

```bash
node scripts/bump.mjs show     # 看当前版本
node scripts/bump.mjs patch    # 小改动：1.1.72 -> 1.1.73
node scripts/bump.mjs minor    # 成体系升级：1.1.73 -> 1.2.0
```

脚本会同时改 `package.json` 与 `client.js` 里的 `vX.Y.Z` chip，并对 `major > 1` 直接报错拦下。

## 两条硬约束

1. **面板门槛**：`client.js` 的 `skillUiAllowed()` 要求 `major>1 || minor>1 || (minor==1 && patch>=12)`。低于 `1.1.12` 会把 Skill 段整体隐藏，所以主线不要回退到 1.1.11 或更低。
2. **tag 不删**：历史 tag（`v2.0.0` / `v2.1.0` / `v2.2.0` / `v1.1.72`）保留在仓库里作为走过弯路的记录，新版本只往前加 tag，不改旧 tag。
